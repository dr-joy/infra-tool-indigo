## Admin bật/tắt riêng "vùng cá nhân" Release cho TỪNG USER (thay cơ chế vừa revert ở trên)

**Leader nói:** muốn Admin (không phải tự user) cấu hình bật/tắt cả "vùng cá nhân" (nút cạnh "Lịch
chung", gồm CẢ phần tự sinh task theo lịch team LẪN phần tự tạo template/task riêng vốn không liên
quan team nào) theo TỪNG NGƯỜI — chỉ user thuộc team đủ điều kiện (release + Tab cá nhân + autogen
đều Bật) mới xuất hiện để Admin chọn, người khác không thấy setting này. Mặc định Tắt.

**Claude hỏi trước khi làm** (loạt câu hỏi coaching): phạm vi ẩn (chỉ phần tự-sinh-theo-team hay cả
vùng) → Leader chọn **cả vùng**; điều kiện khi 1 user thuộc nhiều team → sau khi chỉ ra mâu thuẫn
(toggle theo từng team nhưng dữ liệu template/task lại dùng CHUNG không theo team, sẽ tự ẩn/hiện vô
lý khi đổi qua lại giữa các team) Leader chọn **bật/tắt là 1 giá trị chung theo user, không theo
team**; migrate user cũ đã có dữ liệu → Leader chọn **mặc định Tắt cho TẤT CẢ, kể cả user cũ** (chấp
nhận đánh đổi: user đang dùng tự do sẽ mất quyền truy cập ngay sau khi deploy tới khi Admin bật lại);
UI khi ẩn → **ẩn hẳn nút, không giải thích gì**.

**Phát hiện quan trọng khi khảo sát code (báo lại Leader trước khi code vì phạm vi lớn hơn tưởng):**
cơ chế phân quyền `authorizePersonalTask()` (policyKind `personal_task`) đang dùng CHUNG cho 3 tính
năng khác nhau — Mind Map (`mindmaps.ts`), Task cá nhân nói chung (`tasks.ts`/`schedules.ts`), và
"vùng cá nhân" Release (`release.ts`/`schedules.ts`/2 route sinh task ở `release-schedule.ts`). Sửa
thẳng hàm dùng chung đó sẽ vô tình khoá luôn Mind Map + Task cá nhân của mọi người — thay vào đó thêm
1 hàm RIÊNG (`assertPersonalReleaseAreaEnabled()`), gọi thêm đúng ở các route thuộc vùng cá nhân
Release, không đổi hành vi 2 tính năng kia.

**Đã làm:**
- Bảng mới `user_release_personal_area_pref` (user_id PRIMARY KEY — không có team_id, vì template/
  task cá nhân vốn dùng chung không theo team; `updated_by` — Admin set, không phải self-service).
- `server/lib/authorize.ts`: `assertPersonalReleaseAreaEnabled()` (throw 403 nếu chưa đủ điều kiện
  HOẶC Admin chưa bật riêng) + `personalReleaseAreaEnabled()` (bản không throw, cho route đọc trạng
  thái). Gọi thêm hàm đầu ở: 16 route trong `release.ts` (qua helper `requirePersonalOwn()` + 8 chỗ
  PATCH/DELETE gọi trực tiếp), toàn bộ 8 route `schedules.ts` (qua 1 điểm chung
  `requireOwnPersonalTaskSchedule()`), 3 chỗ + route mới `GET .../personal-area-status` trong
  `release-schedule.ts`.
- Admin: `GET/PUT /admin/release-personal-area-users` + `/admin/release-personal-area-pref`
  (`admin-config.ts`, đăng ký resource mới `release_personal_area_pref` trong
  `authorization-policy.ts`) — GET chỉ liệt kê user đủ điều kiện, PUT cũng tự chặn (404) nếu target
  chưa đủ điều kiện — không chỉ ẩn ở danh sách, đúng yêu cầu "không phải user nào cũng setting được".
- FE: `admin.tsx` thêm mục "Vùng Cá nhân trong Release — theo từng người" (danh sách + toggle switch,
  cùng khuôn UI với "Tab cá nhân Release" đã có). `release.tsx`: `ManHinhLenLich` tự fetch
  personal-area-status lúc mount, ẩn hẳn nút "Cá nhân" khi chưa bật (mặc định coi như Tắt trong lúc
  đang tải/lỗi, an toàn hơn loé hiện rồi ẩn).

**Test:** thêm mới `test/integration/release-personal-area-admin.test.ts` (4 ca: user chưa đủ điều
kiện không được liệt kê + PUT từ chối; đủ điều kiện nhưng Admin chưa bật vẫn 403, bật xong 200;
rowVersion cũ → 409; không phải Admin → 403) + `test/client/release-personal-area-visibility.test.tsx`
